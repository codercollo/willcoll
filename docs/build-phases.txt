THE LOOP (every sub-step)
  1. Paste the phase's AGENT PROMPT (with the sub-step id) into Claude Code.
  2. Agent does ONE sub-step, runs the GATE, leaves files for you, reports
     in 3-4 lines, STOPS.
  3. You: git status, commit that sub-step, push, check CI.
  4. Reply "continue".

  GATE  backend: go build ./... · make audit · make test RACE= ·
                 make test/integration
        frontend: pnpm lint · pnpm typecheck · pnpm test · pnpm build
                  (for every app that extends a changed layer)

  STANDING RULES (in CLAUDE.md)
    - Never git commit or push; the user does.
    - One sub-step at a time; stop after each.
    - No behaviour change unless the sub-step says so.
    - Follow system-design.txt; if a decision is missing, stop and ask.
    - Ledger rules: append-only, storno, SERIALIZABLE + retry, zero-sum,
      SET LOCAL tenant_id + RLS. Money never through float.

         sub-step too since it costs nothing without a deploy target yet.
  4b [ ] deploy/: caddy (all hosts), postgres (4 DBs + roles), platform +
         rentals compose files — written for the eventual VPS shape
         (staging, production) even though neither runs yet, so Phase 9
         isn't designing them from zero.
         ALSO this sub-step: deploy/local/docker-compose.yml, a genuinely
         usable local-staging stack — Caddy, Postgres (all 4 databases:
         willcoll_platform, willcoll_rentals, +estates/waste once they

         rentals.localhost) via Caddy's automatic local TLS/host routing —

         exercised exactly as they will be on the real domain, not
         approximated with ports on one host. One Makefile target starts
