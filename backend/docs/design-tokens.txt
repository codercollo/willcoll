-- Status colours as TEXT (added after an automated WCAG AA scan)
The solid status colours above are 3.0-4.0:1 on white, which fails AA for body
text. Use the solid colour for dots, progress bars and borders ONLY. For any
status-coloured text (amounts, badge labels, alerts) use the -text variants:
  status-paid-text       #0F7A52   (5.4:1 on white, 4.8:1 on its tint)
  status-arrears-text    #C0322C   (5.6:1 on white, 4.9:1 on its tint)
  status-partial-text    #9A5B00   (5.4:1 on white, 4.8:1 on its tint)
  status-pending-text    #2557C2   (= blue-700)
  status-unmatched-text  #6D28D9   (7.0:1 on white)
The count pill on the sidebar (white text) uses status-unmatched-text as its fill.

-- Status colours as TEXT (added after an automated WCAG AA scan)
The solid status colours above are 3.0-4.0:1 on white, which fails AA for body
text. Use the solid colour for dots, progress bars and borders ONLY. For any
status-coloured text (amounts, badge labels, alerts) use the -text variants:
  status-paid-text       #0F7A52   (5.4:1 on white, 4.8:1 on its tint)
  status-arrears-text    #C0322C   (5.6:1 on white, 4.9:1 on its tint)
  status-partial-text    #9A5B00   (5.4:1 on white, 4.8:1 on its tint)
  status-pending-text    #2557C2   (= blue-700)
  status-unmatched-text  #6D28D9   (7.0:1 on white)

Contrast rule: every text/background pairing above meets WCAG AA (4.5:1
body text, 3:1 large text/icons). navy-950 sidebar text is always white or
navy-400 (never gray-500 or navy-500, which fail on navy-950).

3. TYPOGRAPHY
--------------------------------------------------------------------------------
Font family (via @nuxt/fonts): "Inter", system-ui fallback stack. Matches
the geometric, tight-letterspacing sans in the reference screenshot.
Numerals: tabular-nums enabled globally on any element carrying a Kshs
amount, a meter reading, or a unit number — ledgers and spreadsheet grids
must have digits align in columns.

  --font-family-base   'Inter', ui-sans-serif, system-ui, sans-serif
  --font-feature-nums  'tnum' 1     -- applied to .money, .reading, table <td> numerics

  Scale (name / size / line-height / weight / usage):
  display    28px / 36px / 700   Page hero numbers only (rare — e.g. "Grand
                                   Total Payment" on the generated schedule
                                   PDF preview, not in normal UI chrome)
  h1         22px / 30px / 700   Page title ("Properties", "The Silver
                                   Square" property name header)
  h2         18px / 26px / 600   Card section headers, tab panel titles
  h3         15px / 22px / 600   Card titles (PropertyCard name, UnitCard
                                   tenant name), table column group headers
  body       14px / 20px / 400   Default body text, table cell text, form
                                   labels' sibling text
  body-strong 14px / 20px / 600  Emphasized inline values (a balance figure
                                   inline in a sentence)
  label      13px / 18px / 500   Form field labels, table column headers
                                   (uppercase, +0.02em letter-spacing)
  caption    12px / 16px / 400   Helper text, timestamps, receipt numbers,
                                   sidebar section dividers
  money-lg   20px / 26px / 700   Ledger balance figures, card KPI numbers
                                   ("rent collected vs expected")
  money-sm   14px / 20px / 600   Inline table amounts

Letter-spacing: -0.01em on h1/h2 (matches the tight heading in reference),
+0.02em on `label` (uppercase table headers), 0 elsewhere.

7. COMPONENT SPECS
--------------------------------------------------------------------------------
7.1 PropertyCard (Properties page — card grid)
  container: radius-md, shadow-card, surface-card, padding space-6
  grid: 3 columns @ >=1280px, 2 @ >=1024px, 1 @ below
  gap between cards: space-6 (24px) both axes
  layout inside card, top to bottom:
    - property name (h3) + landlord name (caption, gray-500) — gap space-1
    - KPI row (gap space-4 between the two stats):
        "Rent collected vs expected"  -> money-sm value + a thin progress
           bar (4px height, radius-full, track gray-100, fill accent-primary;
           fill color switches to status-arrears if collected < 60% of
           expected past the 20th of the month)
        "Units" -> "37 occupied / 48 total" body text, with a small
           occupied/vacant dot pair (status-paid dot, status-vacant dot)
    - divider (hairline, gray-100), margin-y space-4
    - footer: "View property" as a text link, accent-primary, right-aligned
  hover: shadow elevates to shadow-popover, border tints to blue-100,
         120ms ease-out transition — no layout shift

7.2 UnitCard (Units tab inside a Property)
  more compact than PropertyCard: padding space-4, radius-md, shadow-card
  content: unit_code (h3) top-left, status badge top-right (paid/arrears/
           partial/vacant — see 7.5 Badge), tenant_name (body) below,
           "Leased since {date}" (caption, gray-500)
  grid: 4 columns @ >=1280px, 3 @ >=1024px, 2 @ >=768px, 1 below
  gap: space-4 (tighter than PropertyCard — these are denser, higher-count)

7.3 Tabs (Property page: Units|Rent|Water|Garbage|Reports — Unit page:
     Rent ledger|Water ledger|Garbage ledger)
  height: 44px, sits directly under the property/unit header, no card
          wrapper (full-bleed on content-max-width)
  tab item: padding space-3 space-5, body-strong weight when active
  active indicator: 2px accent-primary underline, gray-300 track underneath
                    the full tab row
  inactive text: gray-500; active text: gray-900
  spacing between tab labels: space-8 (24-32px breathing room, these are
                                click targets a manager taps daily — no
                                dense cramming)

7.4 SpreadsheetTable (Rent / Water / Garbage generation grids — the
     highest-stakes component, directly digitizes the paper ledger)
  container: surface-card, radius-md, shadow-card, NO internal padding
             (the table fills the card edge-to-edge; padding lives in cells)
  header row: sticky top:0, background gray-050, label-style text
              (uppercase, gray-500), height 40px, border-bottom
              border-width-hairline gray-300
  body row height: 48px (tall enough for an inline numeric input without
                    the row feeling cramped — this grid is edited, not just
                    read)
  cell padding: space-3 vertical, space-5 horizontal
  zebra striping: OFF by default (a flat white table reads calmer at 48
                  rows-per-property); instead, hover highlights the row
                  with blue-050 background
  editable cell (current_reading, rate override): input has NO visible
      border at rest (blends into the row), gains border-width-focus
      accent-primary ring + surface-card background on focus — signals
      "this cell is live" without every cell looking like a form at rest
  computed cell (units_consumed, amount, prior balance): text-only,
      money-sm, right-aligned, gray-700 — never editable, never boxed
  arrears/total cell: money-sm, bold, colored via ledger status tokens
      (arrears in status-arrears, fully paid in status-paid) exactly like
      the red-ink annotations in the paper ledger you're replacing
  row-level lock state (after "Generate billing invoices"): row background
      gray-050, all cells become read-only text, a small lock icon (14px,
      gray-500) appears at the row's leading edge
  footer row: sticky bottom:0, surface-card, border-top hairline, holds
      column totals (matches the paper ledger's bottom summary row),
      money-lg weight
  action bar (above the table, not inside it): "Generate billing invoices"
      primary button, right-aligned, space-4 below the tab row, space-4
      above the table card

7.5 Badge / status pill (ledger status, everywhere a balance state shows)
  height: 22px, padding 0 space-3, radius-full, label-size text (13px),
          weight 600
  background: the status's *-tint color; text/dot: the status's solid color
  always paired with a 6px status dot (radius-full) at the leading edge,
  gap space-1 to the text — never color-only (colorblind-safe: status also
  differs by label text: "Paid" / "Arrears" / "Partial" / "Vacant" /
  "Pending" / "Review")

7.6 Buttons
  primary:   height 40px, padding 0 space-5, radius-sm, background
             accent-primary, text white, body-strong; hover
             accent-primary-hover; disabled: gray-300 bg, gray-500 text
  secondary: same sizing, background white, border hairline gray-300,
             text gray-900; hover background gray-050
  destructive (rare — e.g. "Terminate lease"): same sizing, text
             status-arrears, border status-arrears at 30% opacity, hover
             bg status-arrears bg-tint
  icon-only (table row actions, sidebar collapse toggle): 32px square,
             radius-sm, gray-500 icon, hover background gray-100
  button group spacing: space-3 between adjacent buttons in a toolbar

7.7 Forms (Sign up/in, Account, and the Tenant pay-intent form especially
     — this is the form a non-technical tenant fills on a phone, so it
     gets the most generous spacing of any form in the system)
  field stack gap: space-5 (20px) between fields — more than the space-4
                    default, because mis-taps on a phone are costly here
  label: label style, margin-bottom space-2, always visible (no
         placeholder-as-label anti-pattern)
  input: height 44px (comfortable tap target), radius-sm, border hairline
         gray-300, padding 0 space-4, focus -> border-width-focus
         accent-primary + subtle accent-primary-tint glow
  helper/error text: caption size, margin-top space-1; error text uses
         status-arrears color and an inline 14px warning icon
  amount input (payment intent lines): right-aligned, tabular-nums,
         money-sm, prefixed with a static "Ksh" affix (gray-500, not
         inside the editable area) — mirrors how every paper document
         studied writes amounts
  submit button: full-width on the tenant pay page (mobile-first), height
         48px (slightly taller than the 40px desktop default — thumb
         target), sits space-6 below the last field, never sticky/floating
         (a fixed bottom bar is where accidental double-taps happen)

7.8 Tenant public pay page layout (the one screen a non-manager ever sees)
  single card, radius-lg (matches the reference's rounded hero panel
  language), max-width 480px, centered, surface-card, shadow-popover,
  padding space-8
  vertical rhythm, top to bottom: property name + unit code (h2), OTP step
  OR balances summary (each ledger type as a compact row: label left,
  money-sm right, status badge inline), divider, PayIntentForm (7.7),
  submit, then a live STK-push status stepper (three states: "Sent to your
  phone" / "Waiting for PIN" / "Confirmed" — each state a horizontal step
  with a 24px icon, connected by a 2px gray-300 line that fills
  accent-primary as it progresses) — no page reload, polls
  /v1/pay/intents/:id/status

7.9 Reports tab (generates the physical documents)
  period picker + two primary actions ("Generate schedule PDF", "Generate
  receipts PDF") in a toolbar, space-4 below the tab row
  totals preview: a read-only summary table mirroring the exact columns of
  "ALL IN ONE PAYMENTS SCHEDULE" (Hse No. | Tenant | Rent Paid | Water
  Bills Paid | Rent Deposit | Water Deposit | Total) so the manager
  reviews on-screen in the identical shape as the PDF they're about to
  hand the landlord — no surprises between preview and export
  garbage column in this preview is entirely omitted (not grayed out,
  not shown-as-zero) when the property's garbage_enabled is false,
  matching the spec's "garbage can be ignored/omitted"

7.10 KPI stat tiles (Properties page header, Admin dashboard)
  height 88px, radius-md, surface-card, shadow-card, padding space-5
  layout: caption label top (gray-500), money-lg value below, optional
  small delta/trend caption (status-paid or status-arrears colored)
  grid gap space-4, 4-up on desktop, 2-up on tablet, 1-up on mobile

10. DARK-SURFACE / LIGHT-SURFACE RULE (where each theme applies)
--------------------------------------------------------------------------------
Willcoll is NOT a dark-mode app end to end — the reference image itself
only darkens the navigation chrome. Applied consistently:
  DARK  (navy-950/900/800 + white/navy-500 text): sidebar only, on every
        shell (manager, admin). Never the content canvas, never a card,
        never a table, never the tenant pay page.
  LIGHT (gray-100 canvas, white cards, gray-900 text): everything else —
        all forms, all ledgers, all spreadsheet grids, all generated
        document previews, the entire tenant-facing surface.
Rationale: ledgers and spreadsheet grids are read for long stretches and
compared against printed PDFs in good light (a manager sitting with the
paper ledger book open beside the screen, per the actual workflow) — high
sustained contrast and print-adjacent color wins there over a full dark
theme, while the navy sidebar still gives the app the confident, branded
identity of the reference screen.
