HOW EVERY PHASE RUNS (the loop)
--------------------------------------------------------------------------------
  1. Paste the phase's AGENT PROMPT into Claude Code (repo root).
  2. The agent does ONE sub-step, runs the GATE, stages the files, reports in
     3-4 lines, and STOPS.
  3. You: `cd ~/Desktop/willcoll && git status`, then commit that sub-step
     yourself, then push, then check that CI is green.
  4. Reply "continue". Repeat until the phase is DONE.
  5. At a phase's end, tick it in the STATUS table below.

  GATE (every sub-step, no exceptions):
    go build ./...  ·  make audit  ·  make test RACE=  ·  make test/integration
    frontend sub-steps also: pnpm lint · pnpm typecheck · pnpm test · pnpm build

  STANDING RULES (paste once per session, already saved in CLAUDE.md):
    - Never git commit, never git push. Stage only; the user commits.
    - One sub-step at a time; stop after each with a short report.
    - No behaviour change unless the sub-step says so.
    - internal/shared never imports a product package.
    - Ledger rules: append-only, storno, SERIALIZABLE + retry, zero-sum,
      SET LOCAL tenant_id + RLS.
    - If a step needs a design decision not in docs/, stop and ask.

================================================================================
IF SOMETHING GOES WRONG
================================================================================
  - A gate fails and the agent can't fix it without a logic change: stop,
    `git restore --staged . && git checkout -- .` to drop the attempt, and
    rethink the sub-step.
  - A pushed commit breaks CI: `git revert <sha>` (never force-push shared
    branches).
  - Production data issue after a deploy: restore from the pre-deploy
    pg_dump that _deploy.yml takes, then investigate on staging.
