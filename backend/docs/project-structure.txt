curriculum; frontend follows Nuxt 4 conventions.

│   └── workflows/
│       ├── test.yml                   # Trigger: push/PR targeting `development` ONLY.
│       │                              # This is the sole gate on that branch — go vet,
│       │                              # golangci-lint, `golang-migrate up` + `sqlc generate
│       │                              # --dry-run` against an ephemeral Postgres service
│       │                              # container, `go test ./... -race`. Nothing is
│       │                              # deployed from this workflow; a failing run simply
│       │                              # blocks the PR from merging into `staging`.
│       ├── deploy-staging.yml         # Trigger: push to `staging` (i.e. a merge from
│       │                              # `development`). Re-runs the same test suite as a
│       │                              # safety net, then — only if it passes — builds the
│       │                              # multi-stage Docker image, pushes it to the
│       │                              # registry, SSHes into the staging Compose stack,
│       │                              # runs migrations, and does `docker compose pull &&
│       │                              # up -d`. This is the only workflow allowed to touch
│       │                              # the staging server.
│       └── deploy-production.yml      # Trigger: push to `main` (i.e. a merge from
│                                      # `staging`, normally via a tagged release). Same
│                                      # build-and-migrate steps as staging, targeting the
│                                      # production Compose stack, plus a pre-deploy
│                                      # `pg_dump` logical snapshot taken as a rollback net
│                                      # before migrations run. This is the only workflow
│                                      # allowed to touch the production server.
│       #
│       # Branch flow this enforces:  development --(test.yml gates PR)--> staging
│       #                             --(deploy-staging.yml)--> main --(deploy-production.yml)
│       # Nothing merges to `staging` or `main` without test.yml having passed on the PR
│       # into it, and only `staging`/`main` pushes are wired to a deploy workflow at all —
│       # `development` can never accidentally deploy anywhere.
