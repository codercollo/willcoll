willcoll/                              # Single monorepo — one backend, one frontend, ONE shared deployment
│                                       # hosting MANY independent letting businesses (Organizations, spec
│                                       # §1a). Multi-tenancy is a core, day-one design constraint, not a
│                                       # bolt-on: every business-data table carries organization_id and is
│                                       # protected by Postgres Row-Level Security, and every Organization can
│                                       # dynamically brand its own instance with its own business name/logo/
│                                       # accent color (spec §1b) — "Willcoll" is just the name of the default/
│                                       # first Organization, not the platform's only identity. Backend follows
│                                       # the Standard Go Project Layout (github.com/golang-standards/
│                                       # project-layout) so that /internal, /pkg, and /cmd carry their
│                                       # conventional Go meaning — not just loosely-organized folders. Renter
│                                       # Tenants never touch the Nuxt back-office UI in this repo — their
│                                       # entire experience is SMS (internal/notify), branded with their own
│                                       # Manager's Organization name, plus, when a Manager has a verified
│                                       # IntaSend sub-account, an SMS-linked M-Pesa/card checkout
│                                       # (internal/payments, spec §5.5). Managers and Agents are reached only
│                                       # by SMTP email (internal/mailer), also Organization-branded.
│                                       # NOTE — naming collision, resolved once here: "Organization" always
│                                       # means the SaaS tenancy boundary (a letting business); "Tenant" always
│                                       # means the renter. Never conflate the two, in code or in comments.
│                                       # CODE STYLE — object-oriented throughout: every internal/* package
│                                       # that has behavior exposes a `Service` struct with a constructor
│                                       # (`NewService(...) *Service`) holding its dependencies; internal/domain
│                                       # types are entities carrying the methods intrinsic to their own
│                                       # fields. Handlers are thin controllers that call one service method
│                                       # each — never a bare package-level function performing business logic.
│
